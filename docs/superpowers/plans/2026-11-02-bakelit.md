# bakelit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `bakelit::bake!` turns data files (14 formats) into typed `static`/`const` items at compile time, with strict conversion, inference, and file:line:path errors.

**Architecture:**
- **`bakelit-macros`** (proc macro):
  - `syn` parses the invocation into items and type definitions;
  - each format module parses its file into one spanned value model (`Node`);
  - `ty.rs` maps Rust types to a small type model;
  - `convert.rs` checks a `Node` against a type and emits literal tokens;
  - `infer.rs` derives type definitions from a `Node` when none were written.
- **`bakelit`** is the `no_std` facade that re-exports `bake!`.

**Tech Stack:** Rust 2024, MSRV 1.88; `syn` 2 (full), `quote`, `proc-macro2`; parsers: `jsonc-parser` 0.34, `saphyr` 0.3, `toml` 1, `csv` 1, `rust-ini` 0.21, `java-properties` 2, `kdl` 6; own parsers for RON and `.env`. Dev-only oracles: `serde_json`, `json5`, `ron`. `trybuild` for UI tests.

**Spec:** `docs/superpowers/specs/2026-11-02-bakelit-design.md`.

**Starting point:** empty repo `~/projects/macroz/bakelit` (main has the spec and this plan).

- Features, in both crates (the facade forwards them): `json`, `jsonc`, `json5`, `jsonl`, `yaml`, `toml`, `ron`, `csv` (CSV and TSV), `ini`, `env`, `properties`, `kdl` and `frontmatter`. The default set is `json`, `toml`, `yaml` and `csv`.

## Decisions this plan makes (my calls, within the spec)

**The value model,** in `bakelit-macros/src/value.rs`:
```rust
pub struct Pos { pub line: usize, pub col: usize }          // 1-based
pub struct Node { pub value: Value, pub pos: Option<Pos> }
pub enum Value {
    Null,
    Bool(bool),
    Int { negative: bool, magnitude: u128 },   // covers i128 and u128 exactly
    Float(f64),
    Str(String),     // a typed string (JSON, YAML, TOML, RON, KDL)
    Text(String),    // untyped text from CSV/TSV/INI/.env/.properties: parsed into the target type
    Char(char),      // RON 'c'
    List(Vec<Node>),
    Map(Vec<(String, Node)>),            // keys unique (formats reject duplicates), file order
    Named(String, Box<Node>),            // RON `Name(...)`/`Name`: name + payload (Null for unit, List for tuple, Map for struct)
}
```

**Conversion.** `convert(node, ty, &Ctx) -> Result<TokenStream, DataError>`, in `convert.rs`.
- `Ctx` holds the definitions, the file label and the path stack.
- The rules are the spec's.
- A float fits `f32` when `format!("{}", v as f32) == format!("{}", v)`.
- A `Map` fills `&[(K, V)]`. Keys go through `Text` conversion, so the key type can be `&str`, an integer or an enum.
- Enum forms:
  - `Str`/`Text` gives a unit variant;
  - a one-entry `Map` `{variant: payload}` gives a tagged variant;
  - a `Named` value gives a variant or struct by name. For a struct, the name must equal the struct's (after `rename`), or be omitted, as in RON's `(x: 1)`.

**Naming.** `rename_all` follows serde's rules exactly, including the case conversions and how it handles digits. Did-you-mean uses edit distance ≤ 2, or a case-insensitive or `_`/`-` match.

**Paths.** The file is read from `CARGO_MANIFEST_DIR/<path>`. The expansion's tracking constant uses the canonical absolute path, escaped as a string literal.

**Inference.** Implemented in `infer.rs`, following the spec's rules. It produces definitions and, in all other respects, reuses `convert`. Generated types are `pub` and derive `Debug, Clone, Copy, PartialEq`.

**Line endings and the BOM.** CRLF is accepted everywhere. A UTF-8 BOM is stripped for CSV and TSV (Excel writes one) and is an error elsewhere: `remove the UTF-8 byte order mark`.

## Review Focus

1. **YAML 1.1 values.** `enabled: yes` into a `bool` is an error that says to write `true`. `on` into a `&str` is the string `"on"`. `0o17` is 15, and `012` is 12, as YAML 1.2 reads it. *Pinned in Task 4.*
2. **Numbers at the edges.** `u64::MAX`, `i128::MIN` and `u128::MAX` are exact in JSON, YAML, TOML and RON. `1e3` into an `i32` is an error. `0.1` into an `f32` is fine; `0.123456789` into an `f32` is an error suggesting `f64`. *Pinned in Tasks 1, 4 and 5.*
3. **Typos.**
   - An unknown key gets did-you-mean, also after `rename` and `rename_all`.
   - Under inference, two keys that map to one identifier (`max-conns` and `max_conns`) are an error.
   - A Rust keyword used as a key (`type`) becomes `r#type`.

   *Pinned in Tasks 1 and 2.*
4. **Rebuild tracking.** A path containing spaces and non-ASCII characters works. A missing file gets an error naming the full path it tried. *Pinned in Task 1.*
5. **CSV realities.** A BOM, CRLF, quoted fields with commas and newlines, an empty trailing line, a ragged row (an error naming the line), and a header that repeats a name (an error). *Pinned in Task 6.*

### Task 5: RON

**Files:** Create `formats/ron.rs` (an own parser).

**Grammar** (RON's spec):
- whitespace and `//`, `/* */` comments (nested);
- `#![enable(...)]` extensions are an error (`RON extensions aren't supported`);
- values:
  - `true`/`false`;
  - integers (decimal, `0x`, `0o`, `0b`, `_` separators, sign);
  - floats (`1.0`, `1e3`, `inf`, `-inf`, `NaN`);
  - chars `'a'` with escapes;
  - strings `"..."` with escapes and raw strings `r#"..."#`;
  - byte strings: an error;
  - `None`/`Some(v)`;
  - lists `[...]`, maps `{k: v}` (string keys only), tuples `(a, b)`;
  - named forms `Name`, `Name(a, b)`, `Name(f: v)`, and an unnamed struct `(f: v)`;
  - trailing commas.

**Value mapping:**
- `Some(v)` gives v's node;
- `None` gives `Null`;
- a tuple gives `List`;
- `Name(...)` gives `Named`;
- `(f: v)` gives `Map`.

- [ ] **Step 1: Failing tests.**
  - Unit tests for every grammar form, with positions.
  - An oracle sweep (15,000 generated RON strings) against the `ron` crate:
    - acceptance agrees, except for the documented classes (extensions, byte strings, non-string map keys);
    - for accepted inputs, our structure with names dropped equals `ron::Value` (numbers compared by value).
  - Integration: enums with unit, tuple and struct variants, nested named structs, and Review Focus 2's edges.
- [ ] **Step 2-4.**
- [ ] **Step 5: Commit** `RON with struct and variant names`.
